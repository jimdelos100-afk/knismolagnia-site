KNISMOLAGNIA.CLUB V5.6 升级说明

本次改动
1. 昵称可以提交修改申请，管理员审核通过后才生效。
2. 头像第一次上传和后续更换都必须提交审核。
3. 每位用户同时只能有一条待审核资料申请；管理员处理前不能再次提交。
4. 全站配色调整为淡粉色，并保留原有页面框架与权限逻辑。
5. Level 3、Level 4 增加作品发表模板示例。
6. 作品字段包括：封面、标题、作者、页数、简介、标签、完整说明和附件。
7. Level 3、Level 4 都可以提交作品投稿，投稿只进入管理员后台审核。
8. Level 3、Level 4 前台每页显示 12 条；后台内容和投稿每页显示 20 条。
9. 前后台增加作品检索。
10. 管理员可以设置排序值；数字越小，同一 Level 中显示越靠前。

重要说明
- 本升级不删除任何用户、资料、投稿、关注或作品。
- 密码继续要求至少 8 位。
- 原 009 文件已经改为安全版本，不再自动删除历史未验证账号。

操作顺序

第一步：升级 Supabase 数据库
1. 登录 Supabase。
2. 进入 SQL Editor，点击 New query。
3. 打开下面这个文件并复制全部内容：
   supabase/migrations/20260918003533_profile_review_and_work_catalog.sql
4. 粘贴到 SQL Editor，点击 Run。
5. 成功时应显示 Success，不能出现红色错误。

当前数据库已经具备 009 的实名认证、私密留言和审核来源结构，因此不需要再次运行 009。
如果以后重建数据库，项目内的 009 已经是不会删除历史数据的安全版本。

第二步：替换 GitHub 文件
1. 按照压缩包内的原路径覆盖同名文件。
2. 不要删除 .env.local，不要修改 Vercel 环境变量。
3. 提交到原来的 GitHub 仓库。

第三步：等待 Vercel 自动部署
1. 打开 Vercel Deployments。
2. 等待最新一次部署显示 Ready。
3. 打开网站后退出账号并重新登录，再强制刷新页面。

测试顺序
1. 普通账号进入个人资料，选择新昵称或头像并提交。
2. 提交后确认不能再次提交第二条申请。
3. 管理员进入“资料修改审核”，通过申请。
4. 普通账号刷新，确认昵称或头像已更新。
5. 打开 Level 3 和 Level 4，检查模板、检索和分页。
6. 管理员进入“Level 内容”，填写封面、标题、作者、页数、简介和标签。
7. 修改排序值，确认数字较小的作品显示在前面。

如果 SQL Editor 出现红色错误，请停止操作，不要重复运行，把完整错误截图发来。
